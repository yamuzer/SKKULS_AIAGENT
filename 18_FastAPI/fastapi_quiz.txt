#실습1 - Course Catalog CRUD API


## 제공 데이터
data/courses.json

- 총 360개 강의 데이터
- category: python, data, ai, web, database, cloud
- level: beginner, intermediate, advanced

## 구현할 프로젝트 구조

```text
app/
├─ main.py
├─ data/
│  └─ courses.json
├─ routers/
│  ├─ __init__.py
│  ├─ health.py
│  └─ courses.py
├─ schemas/
│  ├─ __init__.py
│  └─ course.py
└─ services/
   ├─ __init__.py
   └─ course_service.py
```

## 문제 1. CourseCreate 모델 작성

다음 필드를 갖는 `CourseCreate`를 작성한다.

- title: 문자열, 3~80자
- category: python / data / ai / web / database / cloud 중 하나
- level: beginner / intermediate / advanced 중 하나
- price: 0원 이상, 3,000,000원 이하
- seats: 0~500
- active: 기본값 True
- instructor: 문자열, 2~30자

### 추가 검증
`field_validator`를 이용한다.

1. title 앞뒤 공백 제거
2. instructor 앞뒤 공백 제거
3. title을 공백 제거한 결과가 비어 있으면 오류

## 문제 2. 목록 조회

GET /courses

다음 Query Parameter를 선택적으로 받을 수 있게 한다.

- category
- level
- max_price
- active
- limit: 기본값 20

조건이 주어진 경우에만 필터링한다.

반환 예시:

```json
{
  "count": 2,
  "courses": [
    {
      "id": 1,
      "title": "...",
      "category": "python",
      "level": "beginner",
      "price": 63700,
      "seats": 22,
      "active": true,
      "instructor": "..."
    }
  ]
}
```

## 문제 3. 단일 조회

`GET /courses/{course_id}`

- 존재하면 해당 강의 반환
- 없으면 404

## 문제 4. 강의 생성

`POST /courses`

- 성공: 201
- id는 현재 가장 큰 id + 1
- 같은 title이 이미 있으면 409
- title 비교 시 대소문자 및 앞뒤 공백 차이는 무시

## 문제 5. 강의 수정

`PUT /courses/{course_id}`

- 존재하지 않으면 404
- 다른 강의와 title이 중복되면 409
- 전체 데이터를 수정

## 문제 6. 강의 삭제

`DELETE /courses/{course_id}`

- 존재하지 않으면 404
- 성공 시 삭제 메시지 반환

## 문제 7. health router

`GET /health`

```json
{
  "status": "ok",
  "message": "server is running"
}
```

## 실행

```bash
uvicorn app.main:app --reload
```

Swagger:

```text
http://127.0.0.1:8000/docs
```

## 확인용 요청 예

GET /courses?category=python&level=beginner&max_price=200000&active=true&limit=5
GET /courses/10
GET /courses/9999

#실습2 - File Upload and CSV Analysis API


## 제공 데이터

### 1. support_tickets.csv
data/support_tickets.csv

- 총 600행
- 고객 문의 데이터

컬럼:

- ticket_id
- created_date
- customer_name
- category
- priority
- channel
- status
- response_minutes
- agent
- message

### 2. notes
data/notes/

- TXT 파일 24개
- 다중 업로드 및 preview 테스트용

## 구현할 프로젝트 구조


app/
├─ main.py
├─ routers/
│  ├─ __init__.py
│  └─ files.py
├─ schemas/
│  ├─ __init__.py
│  └─ file.py
└─ services/
   ├─ __init__.py
   └─ file_service.py

uploads/


## 조건

허용 확장자:
.txt
.csv


최대 파일 크기:
2MB

## 문제 1. 파일 정보 확인

`POST /files/info`

UploadFile 하나를 받아 다음을 반환한다.

- filename
- content_type
- size

파일 포인터를 끝으로 이동하여 크기를 얻은 뒤 반드시 처음으로 되돌린다.

## 문제 2. 텍스트 미리보기

`POST /files/preview`

- txt, csv만 허용
- 최대 2MB
- UTF-8 또는 UTF-8-SIG
- 앞 500글자 반환

반환:

```json
{
  "filename": "sample.txt",
  "characters": 1200,
  "preview": "..."
}
```

## 문제 3. CSV 분석

`POST /files/analyze-csv`

CSV 파일만 허용한다.

필수 컬럼:

```text
ticket_id
category
priority
status
response_minutes
```

다음을 계산한다.

- total_count
- category_counts
- priority_counts
- status_counts
- unresolved_count
  - status가 resolved가 아닌 행 수
- average_response_minutes

필수 컬럼이 없으면 400 오류를 발생시킨다.

## 문제 4. 파일 저장

`POST /files/save`

- txt, csv만 허용
- 안전한 파일명 사용
- `uploads` 폴더에 저장
- 성공 시 201

## 문제 5. 여러 파일 정보 확인

`POST /files/multiple`

여러 파일을 업로드받아 각 파일의

- filename
- content_type
- size

를 반환한다.

## 실행

```bash
uvicorn app.main:app --reload
```

## Swagger 테스트 순서

1. `/files/info`에 `support_tickets.csv` 업로드
2. `/files/preview`에 TXT 파일 업로드
3. `/files/analyze-csv`에 `support_tickets.csv` 업로드
4. `/files/multiple`에 notes의 TXT 파일 3~5개 업로드
5. `/files/save`로 TXT 또는 CSV 저장
