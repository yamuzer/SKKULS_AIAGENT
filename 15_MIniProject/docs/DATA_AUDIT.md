#### D. 핵심 품질 이슈 및 정규화 규칙
1. **NCS 코드 (`ncsCd`) 정규화 규칙:**
   - 부동소수점 읽기로 인해 전수 `xxxx.0` 형식으로 변환되어 선행 0이 탈락된 현상 확인: `02020302` $\rightarrow$ `2020302.0` (길이 7자리).
   - **공식 정규화 로직 확정:** `ncsCd` NULL이면 NULL 유지 $\rightarrow$ 문자열 변환 $\rightarrow$ trailing `.0` 제거 $\rightarrow$ 8자리 미만 유효 코드에 `zfill(8)` 적용 $\rightarrow$ `VARCHAR(8)` 저장. (비정상 형식 임의 수정 금지, Master 미매칭 코드 임의 변경 금지).
2. **주말/주중 구분 (`wkendSe`) 미정의 코드:**
   - 공식 명세: `0`(해당없음), `1`(주말), `2`(혼합), `3`(주중)
   - 실제 데이터 분포: `NaN` 234,189건(37.8%), `3.0`(주중) 199,255건, **`9.0` 136,789건**, `1.0`(주말) 37,301건, `2.0`(혼합) 12,003건
   - `9.0`은 공식 API 명세에 정의되지 않은 코드이므로 DB에는 문자열 `'9'`로 원본 보존하되, 문서/Agent/UI에서 '기타/미지정'으로 공식 의미처럼 확정하지 않고 `unknown / 공식 명세 미확인 코드` 수준으로 처리한다.
3. **취업률 지표 (`eiEmplRate3`, `eiEmplRate6`, `eiEmplCnt3`):**
   - 약 90% 결측치 존재.
   - **Agent 분석 원칙:** 결측치를 0%나 0명으로 왜곡하지 않고, 반드시 `취업률이 보고된 N개 과정 기준` 형태로 모수/커버리지를 명시하도록 강제.

2. **API 명세서 PDF 아웃라인화:** 텍스트 대신 1,933개 벡터 곡선으로 구성되어 있음. 단, 이 명세서의 주요 컬럼과 필드 의미는 이미 `DATA_DICTIONARY.md`에 전수 정리되어 있으므로 Knowledge Base 구축 시 무리한 OCR 대신 딕셔너리 기반 텍스트 주입 가능.
