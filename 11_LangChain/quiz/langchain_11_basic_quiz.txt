LangChain 복습 실습 — 스마트팜 운영 지식 검색 시스템

[공통 조건]
- 오늘 수업 코드의 구조를 그대로 복사하지 말고 새 데이터 컬럼에 맞게 직접 작성한다.
- API 키는 .env의 GEMINI_API_KEY를 사용한다.
- Chat 모델과 Embedding 모델 이름은 수업에서 사용한 환경에 맞춘다.

================================================================================
실습 1. LangChain 모델 단일 호출
================================================================================
목표: ChatGoogleGenerativeAI 객체 생성과 invoke() 기본 사용을 복습한다.

문제
1) "스마트팜에서 EC와 pH를 함께 관리해야 하는 이유를 초보자에게 4문장으로 설명해 주세요."라는 질문을 작성한다.
2) ChatGoogleGenerativeAI로 모델을 생성한다.
3) invoke()로 질문을 전달한다.
4) 응답 본문, 응답 객체의 타입, response_metadata, usage_metadata를 각각 출력한다.

제한
- google.genai.Client를 사용하지 않는다.
- 프롬프트 템플릿은 아직 사용하지 않는다.

실습 2. SystemMessage + HumanMessage
================================================================================
목표: 역할이 다른 메시지를 이용해 모델의 답변 방식에 제약을 주는 방법을 복습한다.

문제
1) SystemMessage에 "스마트팜 현장 교육 담당자" 역할을 지정한다.
2) 어려운 전문 용어는 바로 쓰지 말고 쉬운 현장 예시를 먼저 들도록 지시한다.
3) 답변은 5문장 이내라는 조건도 준다.
4) HumanMessage에는 "관수 펌프 압력이 낮아질 때 무엇을 먼저 확인해야 하나요?"를 넣는다.
5) 두 메시지를 리스트로 만들어 invoke()하고 결과를 출력한다.

================================================================================
실습 3. 대화 이력 직접 관리
================================================================================
목표: messages 리스트에 HumanMessage와 AI 응답을 순서대로 누적하는 방식을 복습한다.

문제
첫 질문: "이번 점검에서 내가 우선 확인할 설비는 LED 보광등이야. 기억해줘."
두 번째 질문: "내가 우선 확인하기로 한 설비가 뭐였지?"
세 번째 질문: "그 설비를 점검할 때 초보자가 확인하기 쉬운 항목 2개만 알려줘."

조건
- SystemMessage 1개로 대화를 시작한다.
- 매 질문과 AI 응답을 모두 messages에 append한다.
- 마지막에 전체 messages를 순회하며 메시지 번호, 클래스명, 내용을 출력한다.

================================================================================
실습 4. ChatPromptTemplate 변수 사용
================================================================================
목표: 하나의 프롬프트 템플릿을 서로 다른 입력값으로 재사용한다.

필수 변수
- learner_level
- equipment
- symptom
- answer_count

System 메시지는 학습자 수준과 설비를 반영하도록 작성하고,
Human 메시지는 증상과 답변 개수를 반영하도록 작성한다.

입력 A
- learner_level: 초보자
- equipment: 관수 펌프
- symptom: 운전 중 압력이 평소보다 낮다
- answer_count: 3

입력 B
- learner_level: 중급자
- equipment: IoT 게이트웨이
- symptom: 데이터가 일정 간격으로 누락된다
- answer_count: 4

각 입력에 대해 prompt.invoke() 결과의 message 목록과 모델 답변을 출력한다.

실습 5. LCEL 체인 구성
================================================================================
목표: prompt | model 형태의 체인을 직접 구성한다.

문제
1) 실습 4와 다른 ChatPromptTemplate을 새로 만든다.
2) 변수는 season, topic, question을 사용한다.
3) prompt | model 체인을 만든다.
4) 아래 입력으로 chain.invoke()를 수행한다.
   - season: 여름
   - topic: 온실 환경 관리
   - question: 온도는 높고 습도도 높은 상황에서 점검 순서를 알려주세요.
5) 체인의 타입과 응답 텍스트를 출력한다.

실습 7. CSV를 LangChain Document로 변환
================================================================================
목표: 새 CSV 스키마를 읽고 필요한 필드를 page_content와 metadata로 다시 설계한다.

문제
1) csv.DictReader로 smartfarm_operations_480.csv를 읽는다.
2) 각 행을 Document로 변환하는 row_to_document() 함수를 작성한다.
3) Document.id에는 record_key를 사용한다.
4) page_content에는 guide_text를 사용한다.
5) metadata에는 최소 다음 7개를 넣는다.
   - record_key
   - topic_code
   - topic_name
   - subject
   - risk_level
   - equipment
   - season
6) 전체 Document 개수와 첫 3개 Document의 id, 제목, 본문 앞 120자를 출력한다.
7) topic_code별 문서 개수도 집계해서 출력한다.

주의
- 수업 코드의 doc_id/content/title 컬럼명을 그대로 쓰면 오류가 나야 정상이다.
- 새 데이터 스키마에 맞춰 직접 수정해야 한다.

================================================================================
실습 8. RecursiveCharacterTextSplitter로 문서 Chunking
================================================================================
목표: 긴 Document를 chunk로 나누고 부모 문서 정보를 추가한다.

조건
- chunk_size = 180
- chunk_overlap = 40
- separators = ["\n\n", "\n", ". ", " ", ""]
- length_function=len

문제
1) 실습 7의 documents를 split_documents()로 분할한다.
2) 각 chunk에 parent_record_key를 추가한다.
3) 각 부모 문서별 chunk_index를 1부터 부여한다.
4) 각 chunk에 total_chunks도 추가한다.
5) 첫 12개 chunk에 대해 아래 형식으로 출력한다.
   [원본문서] SF-0001
   [chunk] 1 / 3
   [길이] 176
   [본문] ...
6) 전체 chunk 수, 평균 chunk 길이, 가장 긴 chunk 길이를 출력한다.

================================================================================
실습 9. Embedding과 코사인 유사도 검색
================================================================================
목표: embed_query(), embed_documents(), 코사인 유사도 계산을 새 데이터로 다시 구현한다.

Part A — 작은 문장 검색
질문: "저울 숫자가 작업 중 계속 틀어져요. 무엇을 확인해야 하나요?"
비교 문장 4개는 직접 작성하되 다음 서로 다른 주제를 포함한다.
- 전자저울 영점 문제
- 저온창고 습도 문제
- 관수 펌프 압력 문제
- 네트워크 지연 문제

1) 질문은 embed_query()로 임베딩한다.
2) 비교 문장은 embed_documents()로 임베딩한다.
3) 코사인 유사도 함수를 직접 구현한다.
4) 유사도가 높은 순서로 정렬하여 순위와 점수를 출력한다.

Part B — 전체 데이터 임베딩
1) 실습 8의 chunk 본문 전체를 임베딩한다.
2) chunk 수와 embedding 수가 같은지 확인한다.
3) 첫 벡터의 앞 10개 값과 벡터 차원을 출력한다.

Part C — 검색 질문 10개 평가
1) retrieval_questions_72.csv에서 앞 10개 질문을 읽는다.
2) 각 질문을 임베딩하고 전체 chunk와 코사인 유사도를 계산한다.
3) 질문마다 Top-3 chunk를 출력한다.
4) Top-1 chunk의 topic_code가 expected_topic_code와 같은지 True/False로 출력한다.
5) 10개 질문의 Top-1 주제 정확도를 마지막에 출력한다.

================================================================================
실습 10. Vector Store 저장 전 Chunk ID 준비
================================================================================
목표: Chroma에 넣기 전에 chunk마다 중복되지 않는 ID를 만드는 과정을 복습한다.

문제
1) 실습 8의 chunk_documents를 사용한다.
2) 각 chunk에 parent_record_key와 chunk_index가 이미 있다는 전제로 진행한다.
3) 다음 규칙으로 ID를 만든다.
   SF-0001-K001
   SF-0001-K002
   SF-0002-K001
4) 생성한 ID를 chunk_ids 리스트에 저장한다.
5) 아래 검증을 수행한다.
   - chunk_ids 개수 == chunk_documents 개수
   - len(set(chunk_ids)) == len(chunk_ids)
   - 앞 10개 ID 출력
6) BASE_DIR 아래에 "chroma_smartfarm_review" 경로 객체를 만든다.
7) collection 이름은 "smartfarm_operations"로 지정한다.
8) Chroma 클래스를 import하고, 저장에 필요한 경로·collection 이름·embedding 객체·chunk_ids가 모두 준비되었는지 출력한다.

주의
- 오늘 제공된 수업 코드 범위에 맞춰 "저장 직전 준비"까지만 한다.
- 실제 Chroma 생성/저장은 이번 복습의 필수 범위가 아니다.
